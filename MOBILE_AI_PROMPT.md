## THE PROMPT (copy from here down)

You are building **BrailleBridge Mobile**, the official Android (Kotlin) companion app for the BrailleBridge project — a braille chording keyboard (ESP32 hardware) with a teacher platform. The app must look and behave **exactly** like the existing teacher platform, connect **only via Bluetooth LE**, and speak the **exact same protocol** as the existing desktop/web software. This is a parity port, not a redesign.

### 1. Mission and hard constraints

1. **Bluetooth only.** No USB serial, no cloud backend, no accounts server. The ESP32 streams over BLE NUS; the app connects directly to it.
2. **BLE proxy service:** a foreground `BleProxyService` starts when the app launches (not when the user opens a screen). It scans, auto-reconnects, reassembles lines/UTF-8, filters boot garbage, and broadcasts every complete line to the UI layer — exactly mirroring `relay.py`. The rest of the app never talks to Bluetooth directly.
3. **Protocol parity is non-negotiable.** Every rule below is already implemented on the device and desktop; do not reinterpret, rename, or "improve" any of it:
   - Device advertises/connects as **"BrailleBridge"**; prefer auto-connect (`createBond`-less reconnection) and request **MTU 247**.
   - Subscribe to NUS TX (`6E400002…`) notifications; write language commands to NUS RX (`6E400003…`).
   - Lines end with `\n`. Data lines are plain characters (a character per chord result); control lines start with a prefix:
     - `LANG:en` / `LANG:bn` — device language toggled (dispatch to UI, also update your UI state)
     - `SYSTEM:BKSP` — delete the last character (student output, teacher feed, exam feed, mirror — everywhere)
   - **UTF-8 reassembly:** a multi-byte Bangla character (or any non-ASCII) may split across BLE packets. Buffer incomplete sequences exactly like `relay.py` does.
   - **Boot filter:** for ~1.5 s after connect, drop ESP32 boot/log lines (`rst:`, `load:`, `entry`, `boot:`, non-UTF-8 noise) so garbage never reaches the display.
4. **Feature parity checklist** (all must exist):
   - **Student view** — live output stream (character-by-character append, backspace removes), language LEDs EN/বাংলা, dot keypad simulator, Shift toggle, clear button, live translate bar.
   - **Teacher view** — live feed, per-student roster (add/remove/persist), student switching, per-student export.
   - **Exam mode** — locked-down feed, copy protection, exam stats, per-student exam export.
   - **Exports tab** — every export auto-saves to a persisted library; review screen renders the **auto-formatted** document (real title/heading/paragraph/list typography, gold rule under titles), Raw mode (timestamped lines), Translate (any catalogue language), Download `.txt` (via SAF), delete/clear.
   - **Auto-formatter** — port `BBAutoFormat` from `shared.js` rule-for-rule: title detection (short line, few words, no terminal punctuation), heading keywords (`chapter`, `অধ্যায়`, `section`, `অনুচ্ছেদ`, `lesson`, `পাঠ`, …), bullets (`*`, `-`, `•`), numbered lists, paragraph joins, space/punctuation normalization.
   - **Google Translate** — full catalogue (**all ~128 languages** Google Translate supports; port the `LANGUAGES` table from `shared.js` verbatim), source `auto`, display `(detected → target)` caption, cache results, native language dropdown defaulting to English. Present in: student live bar + every export review screen.
   - **Teacher account UI** — chip (initials avatar + name) opening a profile modal for **Samin Yeasar**, role **Teacher — BrailleBridge**, ID **BB-T-0001**, verified badge, live stats (students / exports / characters), contact rows, sign-out button (cosmetic). It must look legitimate — polish matters.
   - **Theme** — port the exact navy/gold palette and IBM Plex fonts from `braille-display/style.css` + `shared.css`; support light and dark (the platform supports both).
5. **Tech stack (from PHONE.md §4):** Kotlin, Jetpack Compose, Material 3, MVVM (`ui/`, `data/`, `ble/`, `protocol/`), `AndroidX Bluetooth LE` APIs, `OkHttp` + `kotlinx.serialization` for translate, Room or DataStore for exports/roster, foreground service with `BLUETOOTH_CONNECT` / `POST_NOTIFICATIONS` runtime permissions (API 31+).
6. **Quality bar:** no `!!`, all strings in `strings.xml`, min SDK 26, target latest stable. The app must survive: device power-cycled mid-session (boot filter + auto-reconnect), Bangla split across packets, BLE drop/reconnect without app restart, and rapid backspace taps.

### 2. Definition of done

Run through the acceptance checklist at the end of `PHONE.md` — every box must pass, including:
- Character typed on the device appears in the app within ~100 ms; `SYSTEM:BKSP` deletes it in every view.
- `LANG:en`/`LANG:bn` lines update the app's language state.
- Translate works **to any of the ~128 catalogue languages** and the `(detected → target)` caption shows the right names.
- Export → appears in Exports → review shows formatted document → translate → download matches the on-screen text.
- Account modal shows live stats.
- All UI matches the navy/gold platform theme in both light and dark.

If anything in this prompt conflicts with `PHONE.md` or the reference code, **the reference code wins** — port it, don't redesign it.
